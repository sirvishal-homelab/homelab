Implementation strategy

Thin slices, each one demoable

Slice 0

Foundations

Container builds in CI, health check is green, a backup file appears.

Slice 1

Events and first image

Add a repeating event and see it drawn in the week image.

Slice 2

Categories and people

Create a category, assign an owner, see initials on the picture.

Slice 3

Views and editor

Build a view and watch a live preview at the panel’s real size.

Slice 4

Push to Terminus

Edit on a phone; the display changes within one check-in.

Slice 5

Polish and operate

Export, conflict warnings, restore drill, honest health check.

Slices 0 to 3 needed no hardware, so they were fully testable before the display was involved. Every slice ended with a trial on a phone or the real panel.

The order matters: we pushed the risky external dependency (the display server) to slice 4, after a short spike to verify how it really behaves, and kept everything before it testable on a laptop. After slice 5 the owner kept adding small requests as separate pull requests: a repeat count, a month page, the work schedule, a battery readout.
