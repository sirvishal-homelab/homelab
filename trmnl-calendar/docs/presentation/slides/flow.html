How an update travels

From a tap on a phone to the wall

01

Edit

Someone saves an event on a phone.

02

Wait 5 s

Edits are batched into one update.

03

Render

Draw a 2-bit PNG and fingerprint it.

04

Changed?

Same fingerprint: stop. New one: tell Terminus.

05

Deliver

Terminus fetches it; the display collects it at its next check-in.

Safety nets: a 15-minute timer re-checks even when nobody edited anything, and a failed push is shown on the Settings page with the reason.

Terminus downloads the image during our request, so the app serves pictures under a fingerprint in the file name and never changes an image in place.

This is the part of the design that surprised us most. We first assumed the display server would fetch the picture later. In practice it fetches it while we are still talking to it, so the picture must already be available at a stable address. Naming each image after its own hash solves that and gives us the "only push if changed" check for free.
