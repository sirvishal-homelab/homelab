Design principles

Six rules we agreed before coding

Design first

Docs and decisions signed off before production code. The prototype stayed reference only.

The app owns the picture

We draw the image. The display server is only the delivery channel.

Boring, local tech

SQLite, one process, no build step. It runs on a spare home server.

Settings live in data

What users edit is stored in the database. Environment variables hold only secrets and addresses.

A pure core

Calendar rules and drawing never touch the web, database or network. A test enforces it.

Send only what changed

The screen updates only when the picture differs. That saves battery and avoids flicker.

Every rule here has a written decision record (ADR) in the repository. Two are worth dwelling on for a technical audience: the pure core (an automated test fails the build if the drawing code imports anything from the web or storage layers) and "send only what changed" (the app hashes the rendered image and skips the network call when the hash matches).
